# 0002：日志是事实来源，索引是派生视图

- 日期：2026-10-26
- 状态：接受

## 背景

系统有两个子系统：持久化执行引擎和语义记忆索引。它们需要共享数据，但失败模式和一致性要求不同。必须决定：谁是事实来源？

## 选项

1. **引擎状态存数据库，索引单独存向量库**：两套真相，恢复时可能分叉；需要跨存储一致性。
2. **索引作为事实来源**：索引丢失/损坏就无法恢复执行状态，不可接受。
3. **Journal 作为事实来源，索引作为派生视图**：日志顺序追加、可重放；索引异步消费、可重建。

## 决定

采用方案 3：

- Journal 记录 Agent 运行的完整事件序列，是唯一事实来源。
- 记忆索引（HNSW）是 journal 的投影，允许落后、允许重建。
- Episode 使用稳定 ID（`hash(run_id, seq)`），索引不依赖裸 offset 做长期身份。
- Engine 不 import 索引；索引不 import engine；二者只共享事件 schema。

## 后果

- 索引是最终一致；查询要返回 watermark。
- 需要 checkpoint、幂等 upsert、追平/重建机制。
- 日志保留与索引 offset 的关系必须单独设计（MVP 先不截断日志）。
- 故障隔离好：索引挂了不影响写入；恢复路径清晰。
- 面试叙事统一：一条事实来源，一个派生视图。
