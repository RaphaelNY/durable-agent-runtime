# 0003：写路径不等待索引

- 日期：2026-10-26
- 状态：接受

## 背景

Agent 工作流在写完事件后，可能希望立刻能检索到这条记忆。一个自然的诱惑是把索引更新放进写路径，保证"写进去就能查到"。但这会把持久性和检索延迟、索引可用性耦合在一起。

## 选项

1. **写路径同步更新索引**：写入即实时可查；但索引故障/延迟会阻塞 Agent，日志和索引可能部分写入。
2. **异步 indexer 消费 journal**：写入只依赖 journal 落盘；索引最终一致；需要 watermark 和背压。
3. **离线批处理**：实现简单，但新鲜度差；适合分析，不适合 Agent 运行时。

## 决定

采用方案 2：

- Engine 只写 journal，不等待索引。
- Indexer 独立消费，维护 checkpoint；落后时暴露 lag。
- 查询返回 watermark；默认不保证读己之写，需要时显式等待。
- `memory.search` 是普通 activity，有超时和重试；索引故障只影响这一步。

## 后果

- 查询可能看到旧数据；必须在 API 和文档里说清楚。
- 需要 lag 指标、批处理、背压策略。
- 如果业务确实需要读己之写，需要额外的等待/同步机制，不能假设索引实时。
- 失败域清晰：索引崩溃不影响 run 的持久状态。
